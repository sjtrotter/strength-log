The workout as cards you swipe

An exploration, 12 October, evening. The owner asked: instead of a list of exercises, a card per exercise the lifter swipes through, with the sets left shown another way, so the phone mirrors the watch. Two variants below, both on revision 2's decisions (day index, standard checkboxes, goal and last at the right, rest pill only while resting, bottom-sheet editing). Everything is a Material 3 component or a plain composition; the pager is the library's own.

What the watch already does

The watch has two faces. The overview is a dial: an outer ring of program days, an inner ring with one segment per lift that fills green as lifts finish, and a disc that reads Start or Continue over "Set 3 of 6". The workout face shows one set at a time: the prescribed weight and reps, tap the disc to log, then the rest. A swipe left at the start of a set moves to the next lift, wrapping. There is no list on the watch. So a phone that mirrors it has one lift in view, one set in focus, progress as segments, and a horizontal swipe between lifts.

Variant A: one card per lift, all its sets

The ledger's rows, but one lift at a time. The pager replaces vertical scrolling; the segment row replaces the overview.

Variant B: one set in focus, the watch's grammar

The closest mirror. The current set is the biggest thing on the screen, the lift's sets are a row of segments, and there is one action.

Where the current page lives

The page the lifter is on is UI state and survives process death on its own: the pager's state is saveable, so after a kill the app comes back on the same card. The first unfinished lift is derived from the session, so a fresh open lands there; a swipe overrides it only until the next log. Every checkbox and every log still writes to the database on the tap, exactly as the ledger does. Nothing new is held in memory.

Compose contract for the pager

Components. HorizontalPager with rememberPagerState (pageCount from the session's exercise list), key per exercise id, beyondViewportPageCount of one so the peeking card is composed, contentPadding of 20 dp at the start and 40 dp at the end with pageSpacing 12 dp for the peek, PagerDefaults.flingBehavior with its default snap. The segment row is a Row of Box with RoundedCornerShape, each given a 48 dp tall clickable area that calls animateScrollToPage; this is the indicator from Google's own Pager documentation, with a click added. Card for the page, Text in displayLarge with tabular numerals for the set in focus, Button for the log action, FilledTonalButton while a rest runs, TextButton for All sets, ModalBottomSheet for editing and for the list. The app bar has no scrollBehavior; nothing on the screen reads scroll state.

Guidance followed, by title, cited from memory. "Pager in Compose" (state, keys, contentPadding, the indicator sample, scrolling to a page). "Lists and grids" for the sheet list. "Follow best practices" for performance: no backwards writes, no state read in composition that changes every frame; the pager's currentPage is read in a derivedStateOf where it drives the caption. "State and Jetpack Compose" and "Architecting your Compose UI" for hoisting and unidirectional data flow. "Material Design 3 in Compose" for theming through MaterialTheme and the component Defaults. "Accessibility in Compose" for 48 dp targets, mergeDescendants on the set row and a contentDescription on each segment that reads the lift's name and state. "Navigation with Compose" for the workout as its own destination with the navigation bar hidden.

Recommendation

Variant B, if the phone should mirror the watch; otherwise keep the ledger. A is the weaker middle: it gives up the overview and keeps the list, so it pays the cost of both. B pays the overview cost once and buys the biggest numeral the app has ever shown, a screen that never scrolls, and one vocabulary on both devices. The real risk in B is the correction path: a lifter who logged the wrong reps two sets ago needs All sets, then the row, then the sheet. The segments can shorten that: tapping a filled segment opens that set's sheet directly, which is one tap more than the ledger, not two. I would build B with that, keep the ledger's row grammar inside the All sets sheet so nothing is invented, and let the receipt carry the day's record.
